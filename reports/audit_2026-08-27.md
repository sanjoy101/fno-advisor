## 1. Current architecture

Layered, with the dependency direction pointing inward. No circular imports at module
scope; the two places a cycle would occur (`feed` ↔ `live_feed`, `runtime` →
`check_log`) use function-local imports.

```

        │
src/market/               calendar.py (IST, sessions, holidays), event_risk.py
src/costs.py              intraday + delivery cost model, gross/net bound together
        │
src/data/                 fyers_auth.py, backfill.py, bhavcopy.py, india_vix.py,
                          futures.py, announcements.py, corporate_actions.py
        │
src/positions/            models.py (enums, Bar, Position, PositionRuntime)
                          indicators.py, exit_engine.py  ← the decision core
                          feed.py (ReplayFeed, MultiSymbolReplayFeed, BarAggregator)
                          live_feed.py (FyersLiveFeed)
                          store.py (Parquet + DuckDB), replay.py, check_log.py
        │
src/signals/              Module B — built, evaluated, NOT surfaced anywhere
src/analysis/             split.py (DEV/HOLDOUT guard), lookahead.py, momentum.py,

        │
```

Stubs that are docstring-only, with no code: `src/core/`, `src/morning/` (Module A),

**`SessionRuntime` is the only stateful object**, and `SessionRuntime.now()` is the only
mode-dependent read in the entire runtime. Everything else is identical code on
identical data in REPLAY and LIVE — that is the property that makes replay a rehearsal
rather than a different experiment.

## 3. Current Fyers authentication flow

`src/data/fyers_auth.py`, 46 tests. OAuth authorisation-code flow, **2FA manual by
design and structurally so**:

1. `auth_url()` → `SessionModel.generate_authcode()`
2. Human opens the URL, logs in, completes PIN/OTP in a browser
3. Human pastes the full redirect URL back; `extract_auth_code()` parses it, and
   surfaces a Fyers `s=error` payload as an `AuthCodeError` rather than letting an
   empty code fail later as something unrelated
4. `exchange()` swaps the code for a token. **Never retried** — a loop against an auth
   endpoint is how an account gets locked

`prompt` and `out` are injected so the flow is testable *without a terminal* — the
docstring states explicitly that this is not so it can be automated, and that no TOTP
generator should be wired into `prompt`. No TOTP secret exists in settings or `.env.example`.

Five distinct exception types (`TokenMissingError`, `TokenExpiredError`,
`TokenCorruptError`, `AuthCodeError`, base `AuthError`), each with an actionable message.

## 4. Current token storage and expiry handling

- Stored at `data/.fyers_token.json` — inside `data/`, which `.gitignore` excludes
  wholesale (subject to §17: nothing is actually version-controlled).
- `chmod` to owner-only, with an explicit `except OSError: pass` acknowledging Windows
  ACLs differ.
- `TokenBundle.__repr__` and `__str__` are **redacted** — `'<redacted N chars>'` — so a
  traceback or log line cannot leak a live credential. `test_health_never_returns_the_token_itself`
  asserts the API surface too.
- **Expiry is enforced locally, not trusted to the broker**: `is_valid()` requires
  `now.date() == generated_at.date()` AND `now < expires_at`, with `expires_at` pinned to
  23:59:59 IST of the generation day. A token Fyers might still honour at 06:00 the next
  morning is treated as dead here, deliberately.
- `require_token()` is the single entry point for data code; it never falls back to an
  expired token.

**Weak point — see §17.2.** Once the runtime is built, token validity is *reported* but
never *gates advice*.

## 5. Current historical-data flow

`src/data/backfill.py` (874 lines, 86 tests) → `PositionStore` (Parquet, partitioned
`symbol=X/trade_date=Y`, queried with DuckDB; no database server).

- **Resumable** via an append-only JSONL ledger (`data/raw/_backfill_ledger.json`).
  Rewriting it per symbol-day would be quadratic — at ~33,000 settled days that is
  hundreds of GB of writes — so `forget()` is the only compacting path.
- **Rate limited**: 3/s, 100/min, with exponential backoff. Every request logged with
  symbol, range, attempt, row count, duration.
- **Validated on write, quarantined on failure** to `data/quarantine/bars/` with a
  `reason.json` beside it. Never dropped, never stored as if clean.
- `dedupe_bars()` keeps the first copy and *counts* disagreements; a conflict in
  `DECISION_FIELDS` (`high`, `low`, `close`, `volume`) quarantines the day.
  `open` is tolerated, and `test_no_indicator_or_rule_reads_bar_open` pins that premise.
- `last_completed_session()` clamps the range so an unclosed session is never requested.
- `SYMBOL_LISTED_FROM` skips pre-listing ranges; `RETIRED_SYMBOLS` maps dead tickers
  (TATAMOTORS → TMPV/TMCV) to successors.

Secondary sources on disk and rebuildable without a broker token: NSE F&O bhavcopy
(1,641 dates), India VIX (1,640 sessions). Announcements are **forward-collect only**
and must never be backfilled.

## 6. Current live-websocket flow

`src/positions/live_feed.py` (575 lines, 50 tests). **Every network dependency is
injected** — `HistorySource` and `SocketLike` are Protocols and the constructor takes
instances — which is the only reason the reconnect, backfill and staleness paths have
coverage at all.

1. `seed_history()` runs **before** the socket opens, so ATR/EMA21/VWAP are warm rather
   than undefined for the first ~20 minutes. Paced through the shared `RateLimiter`.
2. `start()` connects and subscribes.
3. `_on_message()` drops protocol frames **by type** (`cn`/`sub`/`ful`/…) at debug, then
   parses quotes. An unrecognised type still warns; a frame with `s != "ok"` errors.
4. `close_due_bars(now)` takes the clock as an argument — a bar closes because the minute
   elapsed, not because a tick happened to arrive.
5. `reconnect()` backs off exponentially, then `backfill_gap()` refetches the missed
   minutes and `BarAggregator.merge()` reconciles them. Returns `False` rather than
   raising: a dead feed is a state the UI must show, not an exception that kills the
   process.

**Verification status — must be stated precisely.** Per CLAUDE.md §2.2a, the first live
run was **2026-08-22, a Saturday, with the market shut**. Verified against the real
exchange: websocket connects, authentication succeeds, subscription accepted for 6
symbols, control frames arrive in the expected shapes, `seed_history` classifies a
closed market correctly. **Still unverified: any real tick has ever been parsed** (zero
price ticks arrived), bar aggregation from live ticks, staleness against a real feed
going quiet, reconnect/backfill against a real disconnection, and seeding with actual
bars present. The tick path remains **"tested, unverified live."**

Note `README.md` still says the live feed has *never* run against the exchange and cites
36 tests. That is stale — see §17.6.

## 7. Current replay flow

Two drivers, deliberately different:

- **`replay_session()`** (`src/positions/replay.py`) — batch/offline. Steps at bar close
  times only, evaluates, records transitions. Feeds `batch_replay()` → MAE/MFE →
  `reports/momentum_analysis.md`.
- **`SessionRuntime` in `Mode.REPLAY`** — the dashboard. A virtual clock advances at
  `speed × tick_seconds`, clamped to `last_bar + REPLAY_TAIL` (5 min) so the terminal
  clock is the same at any speed.

REPLAY is the **default** mode and LIVE must be asked for explicitly. Mode, date and
speed are CLI flags only — a test asserts that setting `MODE`/`DASHBOARD_MODE`/`FNO_MODE`
does not change the default.

## 8. Current stale-data detection

Two measurements, one definition each, both in `exit_engine.py`:

| function | measures | threshold | consumer |
|---|---|---|---|
| `feed_staleness()` | tick recency | `stale_feed_seconds` = 30 | exit advice (STALE_DATA) |
| `bars_have_stopped()` | completed bars stopped arriving | 30 + one BAR_INTERVAL | entry check refusal |

`last_tick_at` was unified on 2026-08-25 to mean **"the most recent moment this feed had
data"** in both modes; `data_available_through()` implements it for stored feeds. Before
that, REPLAY meant "close of the last completed bar" and a healthy replayed position
flipped `HOLD → STALE_DATA → HOLD` every minute. `tests/test_feed_semantics.py` (12
functions, 29 with parametrisation) states the invariant directly and asserts LIVE and
REPLAY reach the same verdict *and* the same `PositionState` on equivalent inputs.

Precedence: everything below `FORCE_EXIT` is price-based and **is** suppressed on stale
data. `FORCE_EXIT` outranks `STALE_DATA` because square-off is a clock fact needing no
price, and its attached P&L is labelled stale rather than presented as current.

Entry checks now **refuse** rather than answer on `STALE_FEED` or `MARKET_CLOSED`, and
refusals are not logged to the check scoreboard.

## 9. Current forming-bar handling

`completed_bars(bars, asof)` returns bars where `ts + interval <= asof`. **Every**
indicator and every rule reads bars through it; nothing reads the raw list.
Fyers stamps candles at bar OPEN, and the code compares `asof >= bar_ts + interval`
rather than `asof >= bar_ts`, which is the trap CLAUDE.md §1.2 names.

`BarAggregator` deliberately does not expose the accumulating bucket.

The one place a forming bar is touched at all is `data_available_through()`, and only its
**existence** is read — never its OHLCV. `test_only_the_existence_of_the_forming_bar_is_consulted`
poisons the forming bar's values and asserts the answer does not move. That existence is
not look-ahead: it is exactly what a live socket knows at the same instant.

## 10. Current feature calculations

- **Module C indicators** (`indicators.py`, 9 functions, **9/9 carry a data-availability
  boundary docstring**): session VWAP, ATR(14), EMA(9/21), RSI(14), average volume(20),
  volume ratio. `compute_indicators()` returns `None` per field when history is short —
  unknown is never coerced to zero.
- **Module B features** (`signals/features.py`, 17/19 boundary docstrings;
  `fno_features.py`, 15/20): opening range, EMA/VWAP trend, RSI, ROC, relative volume vs

  divergence, futures basis, India VIX, rollover.

**Look-ahead harness** (`src/analysis/lookahead.py`): every feature evaluated three ways
per timestamp — future bars present, truncated, and **poisoned** (×977). Any disagreement
is a leak. Verified causal on real bars: 56 feature-checks × 16 timestamps × 4 symbols.
Two documented limits: a ratio leak can survive poisoning (pinned by
`tests/test_signal_leak.py`), and cross-session leaks are invisible to it —
`assert_session_causal` is the only cover for that class.

Forbidden-idiom sweep across `src/`: **no `bfill(`, no `backfill(`, no `center=True`, no
`limit_direction`, no `.sample(`, no shuffle, no `import pytz`.** All five
`datetime.now(` sites are `datetime.now(IST)` (tz-aware); four are behind an injectable
`now or …` default and the fifth *is* `now_ist()` itself.

## 12. Current backtesting and validation code

`src/analysis/split.py` (318 lines, 41 tests) is the discipline, enforced structurally:

- Chronological split only. `DevHoldoutSplit.chronological()` puts the whole holdout
  strictly *after* every DEV session.
- `HoldoutGuard.assert_dev_only()` raises if a holdout date reaches a diagnostic.
- `claim()` writes a **fingerprinted claim file to disk**, so a second peek from a fresh
  process still fails. Re-running the *same* config is idempotent and not a peek.
- `SPENT_REGIONS` removes 2026-02-16 → 2026-08-19 entirely: data that has been looked at
  is development data forever.

Claim-file status on disk right now:

| panel | claim file | state |
|---|---|---|
| `PANEL_2026_SPENT` | `reports/.holdout_claim.json` | **SPENT** (momentum analysis) |
| `PANEL_FULL_HISTORY` | `reports/.holdout_claim_full_history.json` | **absent → UNSPENT** ✓ |
| `PANEL_SWING` | `reports/.holdout_claim_swing.json` | **absent → UNSPENT** ✓ |

Statistical discipline is in code, not prose: `Stat` cannot be constructed without `n`;
`verdict()` returns NO CLAIM POSSIBLE below n=30 and DIRECTIONAL ONLY below n=200;
`minimum_detectable_effect()` keeps nulls honest; `effective_n()` corrects for
overlapping and cross-sectional dependence; `sweep_summary()` never recommends a value.

Evaluations completed and reported: signal engine (n=2,368), stop calibration
(n=40,105), single-shot (@09:45 and @10:15), swing (1/3/5-day), F&O positioning
(pre-registered in `reports/.fno_preregistration.json` **before** any P&L was computed),
entry-check diagnostic (n=96,720). Every one is negative or inconclusive, and none was
followed by a threshold nudge.

## 13. Current cost calculation

`src/costs.py` (433 lines, 29 tests). Both an intraday and a **delivery** model.

Components: brokerage (`min(₹20, 0.03%)`), STT/CTT, exchange transaction charge, SEBI
turnover fee, **IPFT** (added because omitting a cost understates it), GST 18% on
brokerage+exchange+SEBI+IPFT, stamp duty (buy side only), and **modelled slippage**
(5 bps/leg default, never zero). Both legs always charged.

`PnLBreakdown` has **no constructor that takes only a gross figure** — gross, costs and
net are bound together by the type. `RoundTripCosts.total` sums both legs.

Delivery costs *more* than intraday despite zero brokerage: 0.338% vs 0.183% round trip
on ₹1,00,000, because delivery STT is 0.1% on **both** legs against intraday's 0.025%
sell-only.

**Status: UNVERIFIED.** `CostSettings.rates_verified` defaults `False`, every rate carries
`TODO(VERIFY)`, `scripts/reconcile_costs.py` exists but **has never been run** — there is
no reconciliation report in `reports/`. No cost-dependent conclusion may be presented as
settled until contract notes are reconciled. The settings docstring correctly separates
*statutory* lines (a mismatch is our error) from *brokerage* (a broker's commercial term,
and the execution broker need not be Fyers).

## 16. Existing safety protections

Ranked by how much they are actually load-bearing:

1. **No order API anywhere.** Source scan + route scan + `ALLOW_ORDER_PLACEMENT`
   validated to reject `True`.
2. **Look-ahead harness with poisoning**, plus `assert_session_causal` for the class it
   cannot see.
3. **Holdout guard with an on-disk fingerprinted claim.**
4. **`PnLBreakdown` cannot express gross-only.** The type enforces §1.4, not a convention.
5. **`completed_bars()` as the single reader** of bar data.
6. **Naive datetimes rejected**, not silently localised. `tzdata` pinned as a hard
   Windows dependency with an actionable re-raise.
7. **Quarantine over deletion** for bad data; append-only ledgers everywhere.
8. **UNKNOWN is a first-class state** in event risk, mode, and check outcomes — never
   rendered as CLEAR/LIVE/OK.
9. **Structural anti-ranking guards** on `/check-entry-all` and `/checks`: no score field
   (recursive banned-key scan), alphabetical/time ordering asserted, no client-side sort
   (static test), identical row classes (browser test), neutral colouring on the change
   column.
10. **Render tests execute the JavaScript** in real headless Chrome and **fail rather
    than skip** when Chrome is absent.

## 17. Existing failures or weak points

Ordered by risk. Nothing here is a test failure — the suite is green.

**17.1 — `.env.example` contains a real-looking Fyers client id.** The committed
placeholder file ends with a pasted `generate-authcode` URL carrying a live-format
`client_id` and the redirect URI. It is not the app *secret*, but it is a credential-shaped
value in a file whose entire purpose is to hold placeholders, and it directly contradicts
CLAUDE.md §3.3. **Fix: delete that trailing line.** (I have not touched it — audit only.)

**17.2 — An invalid token does not gate advice; it only decorates the header.**
`require_token()` is called once when `build_live_runtime()` constructs the feed. After
that, `_token_status()` is display-only. If the token dies mid-session, advice keeps
flowing until the socket drops and `last_tick_at` ages past 30 s. It *does* fail closed —
but **indirectly and with a delay**, through a different mechanism than the one that
knows the truth. This is the single most important Phase 1 item.

**17.3 — `/health` re-reads and re-parses the token file on every call**, and `health()`
is inside `snapshot()`, which runs once per tick (1 Hz) *and* on every `/positions` GET.
That is a file open + JSON parse per second, per client. Functionally harmless, wasteful,
and it means a corrupt token file surfaces as a per-tick exception path.

**17.4 — The F&O ban gate is a stub.** `FnoBanList.is_stub` is `True` and the real NSE
evening publication is not scraped. Current exposure is nil because Module B is not
surfaced anywhere, but §4 requires a banned symbol to be *skipped entirely*, and any
future candidate surface inherits this hole. Participant-wise OI is likewise not built.

**17.5 — Cost rates are unverified and `scripts/reconcile_costs.py` has never been run.**
Every net figure in every report rests on approximations. The code is honest about this
(`rates_verified=False`, `TODO(VERIFY)`), but the reconciliation is a prerequisite for
trusting any cost-dependent conclusion, and the conclusions so far are all cost-dependent.

**17.6 — `README.md` is materially stale.** It claims "1011 tests pass" (now 1,434), that
the live feed has "36 tests" (now 50) and has "never run against the real exchange feed"
(the connection path was verified 2026-08-22 — only the tick path is unverified). A reader
trusting the README would both understate coverage and misstate live status in the safe
direction on one axis and the unsafe direction on another.

**17.7 — No version control.** No `.git`, no history, no revert, no bisect. Every
"append-only, never rewritten" guarantee in the data layer is undermined by a source tree
that can be silently edited with no record. This is the largest process risk in the repo.

**17.8 — SDK log files sit untracked in the repo root.** `fyersRequests.log` (411 KB),
`fyersApi.log`, `fyersDataSocket.log`. I scanned all three for JWT-shaped strings and for
`authorization`/`access_token`/`appIdHash`/`secret_key`: **zero matches**, so nothing is
leaking today. But they are not in `.gitignore`, they grow unbounded, and the SDK controls
what goes into them.

**17.9 — Two API-test matrix gaps.** No test drives the API with an **invalid token**
(only replay's `applicable: False` and the never-leaks assertion), and **"no open
position"** is covered at CLI and browser level but not at the API level.

**17.10 — `NO_SIGNAL` / `NO_TRADE` do not exist as UI states.** The frontend
distinguishes REPLAY/LIVE/UNKNOWN/FEED/TOKEN correctly, and `session_state` carries
CLOSED/PRE-OPEN/SQUARE-OFF WINDOW/OPEN — but as an unstyled text stat, and there is no
module that emits NO_TRADE because Module A does not exist. This is a consequence of the
build order, not a defect, but the brief lists these as required frontend states.

**17.11 — `src/analysis/split.py:357` uses a non-injectable `datetime.now(IST)`** for the
claim timestamp. Tz-aware and not on a decision path, but inconsistent with the clock
abstraction used everywhere else.
